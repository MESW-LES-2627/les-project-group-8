# MVP

A web application where users can create bets for friends. The creator of the bet can invite their friends and program the possible outcomes of the bet. The creator and their friends will be able to choose different outcomes. The creator will be able to decide which outcome was correct. At the end, everyone can keep track of how many bets they got right and how many they got wrong.

## Who is it for?

Groups of friends who create casual, zero-money prediction pools on real-life events and want a single place to settle who was right and track their win/loss record.

## MVP Outcomes (What the user can do)

1. **Create a pool**: Post a pool with a title, statement, deadline, and two possible outcomes.   
2. **Join and pick an outcome**: Open an active pool via invite or dashboard and lock in one of the outcomes before the deadline.   
3. **Resolve the pool**: The pool creator marks the winning outcome once the real-life event finishes.   
4. **Track the scoreboard**: View resolved pools and see a personal tally of total right vs. wrong predictions.

### Core User Journey (MVP Path)

1. User A logs in and creates a bet (title, description, 2 possible outcomes, assigns User B as the decider, and selects friends to invite).
2. The invited friends log in, see the bet on their dashboard, and accept the invitation.
3. Once the event happens, the designated decider (User B) goes to the bet page and selects the winning outcome.
4. The bet status updates to Resolved, and everyone can see who won.

## What Is Out (Saved for the Vision)

1. **Third-party deciders**: Assigning a separate user (User B) as referee is out for the MVP; the pool creator resolves the pool.   
2. **Guest-to-Account upgrades**: Users either use a basic account or a mocked/guest session—no complex account migration flows.   
3. **Weighted pools & custom rewards**: Every pool counts as 1 point (right or wrong). No dynamic odds or custom prize pools.   
4. **Real money or payment gateways**: Strictly bragging rights.
5. **Multiple-select pool**: Allowing users to select more than one outcome.
6. **User input outcome**: Allowing users to input their own outcome.

## Thin Vertical Slice (Iteration 0)

- **The Flow**: A pre-seeded or guest user opens the web app, fills out a form to create a pool with two outcomes, saves it to the database, and sees the newly created pool rendered on the page.   
- **The Stack Check:** Proves the frontend talks to the backend API, and the backend writes and reads the Pool and User models from the database.
