# MVP

A web application where users can create prediction pools for friends. The creator specifies the question, deadline, and two possible outcomes. The creator and their friends choose their outcome before the deadline. Once the event occurs, the creator resolves the pool by picking the winning outcome. Everyone can track their tally of right and wrong predictions on a personal scoreboard.

## Who is it for?

Groups of friends who create casual, zero-money prediction pools on real-life events (sports, reality TV, personal bets) and want a single place to settle who was right and track their win/loss record.

## MVP Outcomes (What the user can do)

1. **Create a pool**: Post a pool with a title, statement, deadline, and possible outcomes.
2. **Join and pick an outcome**: Open an active pool and lock in one of the outcomes before the deadline.
3. **Resolve the pool**: The pool creator marks the winning outcome once the real-life event finishes.
4. **Track the scoreboard**: View resolved pools and see a personal tally of total right vs. wrong predictions.

### Core User Journey (MVP Path)

1. **User A** creates a pool with a title, description/statement, deadline, and distinct outcomes.
2. **Friends** open the pool link, view the details, and select their chosen outcome before the deadline expires.
3. Once the event concludes, **User A (the creator)** resolves the pool by selecting the winning outcome.
4. The pool status updates to `RESOLVED`, and everyone can see who picked correctly and their updated scoreboard.

## What Is Out (Saved for the Vision)

1. **Third-party deciders**: Assigning a separate user (User B) as referee is out for the MVP; the pool creator resolves the pool. (The database schema retains `decider_id` defaulted to `creator_id` for zero-migration forward compatibility).
2. **Guest-to-Account upgrades**: Users either use a basic account or a mocked/guest session—no complex account migration flows.
3. **Weighted pools & custom rewards**: Every pool counts as 1 point (right or wrong). No dynamic odds or custom prize pools.
4. **Real money or payment gateways**: Strictly bragging rights.
5. **Multiple-select pool**: Allowing users to select more than one outcome.
6. **Participant-supplied outcomes**: Participants cannot add outcomes to an existing pool. The creator supplies exactly two labels when creating the pool.

## Thin Vertical Slice (Iteration 0)

- **The Flow**: A pre-seeded or guest user opens the web app, fills out a form to create a pool with two outcomes and a future deadline, saves it to the database, and sees the newly created pool rendered on the page with derived status (`OPEN`).
- **The Stack Check**: Proves the complete stack end-to-end:
  - Frontend UI (SvelteKit 3 on Cloudflare Workers)
  - Backend API (Flask on Render)
  - Database persistence (PostgreSQL on Supabase)
