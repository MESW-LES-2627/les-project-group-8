## Backend reorganization into a modular monolith ([#11](https://github.com/MESW-LES-2627/les-project-group-8/issues/11))

- **Tool:** Cursor agent (Claude).
- **What we asked:** Organize the backend into a simple modular monolith with no over-engineering, remove the in-memory Supabase fallback, and keep the API contract unchanged.
- **What the AI proposed:** One folder per module with the same four files (`routes`, `service`, `repository`, `models`), a `shared/` folder for the database client and errors, and `app.py` reduced to wiring. The in-memory store becomes a test double in `tests/fakes.py`.
- **What we decided ourselves:** Keep `supabase-py` instead of switching to raw SQL with `psycopg` (less change, no new secret), accepting that the pool and its outcomes are two separate inserts. The repository deletes the pool if the outcomes insert fails.
- **How we checked it:** The existing test suite (35 tests) passes against the new structure. A manual run against Supabase returned 200 for `GET /api/pools` (an empty list), but creating a pool was rejected by row-level security because the local `.env` has the publishable key. It also confirmed the app refuses to start without `SUPABASE_URL` and `SUPABASE_KEY`.

## Users module and real pool creators ([#13](https://github.com/MESW-LES-2627/les-project-group-8/issues/13))

- **Tool:** Cursor agent (Claude).
- **What we asked:** Add the first step of the MVP flow (create a user with only a name), and make pools belong to that user instead of a hard-wired guest.
- **What the AI proposed:** A `users` module with the same four files as `pools`. `PoolService` receives a `UserService` and asks it for the creator, so the pools module never reads the `users` table. Field checks shared by both modules moved to `shared/validation.py`.
- **What we decided ourselves:** Users have only a name, and the database stays unchanged. The backend generates the user UUID because `users.id` has no default.
- **What the AI decided (for us to confirm):** An unknown `creator_id` is a **400** (bad request body), not a 404, because the URL `/api/pools` itself exists.
- **How we checked it:** 43 tests pass, including new ones for creating users, name validation, and unknown or malformed creators.

## Acceptance test suite ([#15](https://github.com/MESW-LES-2627/les-project-group-8/issues/15))

- **Tool:** Cursor agent (Claude).
- **What we asked:** Focus the tests on acceptance tests, tied to user stories.
- **What the AI proposed:** Write the user stories with numbered Given/When/Then acceptance criteria, then one HTTP-level test per criterion with a matching name. The old unit tests (`test_domain.py`) and the unstructured API tests were removed, because every rule they checked is now covered through the API.
- **Agreed in the plan we approved:** Keep the fake repositories so tests don't need Supabase. Accept that the Supabase queries themselves are only checked manually for now (documented in `i00.d004-testing.md`).
- **How we checked it:** 36 acceptance tests pass, and every acceptance criterion in `i00.d003-user-stories.md` maps to one test.
