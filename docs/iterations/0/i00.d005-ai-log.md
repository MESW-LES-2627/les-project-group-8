## Backend reorganization into a modular monolith ([#11](https://github.com/MESW-LES-2627/les-project-group-8/issues/11))

- **Tool:** Cursor agent (Claude).
- **What we asked:** Organize the backend into a simple modular monolith with no over-engineering, remove the in-memory Supabase fallback, and keep the API contract unchanged.
- **What the AI proposed:** One folder per module with the same four files (`routes`, `service`, `repository`, `models`), a `shared/` folder for the database client and errors, and `app.py` reduced to wiring. The in-memory store becomes a test double in `tests/fakes.py`.
- **What we decided ourselves:** Keep `supabase-py` instead of switching to raw SQL with `psycopg` (less change, no new secret), accepting that the pool and its outcomes are two separate inserts. The repository deletes the pool if the outcomes insert fails.
- **How we checked it:** The existing test suite (35 tests) passes against the new structure. A manual run against Supabase listed pools correctly, and confirmed the app refuses to start without `SUPABASE_URL` and `SUPABASE_KEY`.
