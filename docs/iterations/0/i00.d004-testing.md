# How to run tests

## Backend setup

From the repository root on Windows PowerShell:

```powershell
py -m venv backend/.venv
& ./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
Set-Location backend
& ./.venv/Scripts/python.exe -m pytest -q
```

On Linux/macOS, use Python 3.13 and the virtual environment's `bin/python`
instead of `Scripts/python.exe`. CI and Render use Python 3.13. The local
verification for Part 1 uses the available Python 3.14 interpreter.

## What Part 1 verifies

- Domain validation: required fields, length limits, exactly two distinct
  outcomes, explicit timezone, future deadline, and UTC normalization.
- Creator/decider selection: request fields cannot override the Guest User.
- Derived status: open before the deadline, locked at the deadline, and resolved
  when a winner is set.
- Flask API: health, creation response, listing, validation errors before storage,
  and generic creation-failure responses.
- Regression cases: stale in-memory status and negative-offset deadline formatting.

Tests use an explicitly injected in-memory store. They require no credentials and
make no network requests. Passing them does not prove database persistence or a
working deployed frontend. Supabase transaction/failure tests belong to the next
implementation block (see `i00.d007-architecture.md`).

Local result on 2026-10-21: **66 tests passed** on Python 3.14. A separate
`python -I -S` smoke check also imported the domain and constructed a valid
`NewPool` without site-packages, Flask, Supabase, or importing `app`.
