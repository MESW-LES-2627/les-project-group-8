# Retrospective

## What went well

The [previous retrospective](../1/i01.d009-retrospective.md) asked for issues
framed so each of us could work independently. Iteration 2 agreed the contracts
up front in [i02.d007.openapi.yaml](i02.d007.openapi.yaml), so [US15](https://github.com/MESW-LES-2627/les-project-group-8/issues/75), [US17](https://github.com/MESW-LES-2627/les-project-group-8/issues/76) and
[US22](https://github.com/MESW-LES-2627/les-project-group-8/issues/77) could start in parallel on day one ([backlog](i02.d008-iteration-backlog.md)).

## What did not go well

We did not estimate the stories at iteration planning. We estimated them
afterwards, on 2026-11-20: closed stories sized from their merged PRs, open
stories by analogy to them. The points are in the
[backlog](i02.d008-iteration-backlog.md); how they were set is in the
[grilling record](../../assets/iterations/2/grilling-story-estimation.md).

The [board](https://github.com/orgs/MESW-LES-2627/projects/24)'s status history
could not tell us how long each story took. [US22](https://github.com/MESW-LES-2627/les-project-group-8/issues/77) skipped "In progress", and
every story was moved back to "To do" and forward again on 2026-11-19, so only
first transitions count, and those measure calendar time, not effort.

A story above 8 points is too big for one iteration; no closed story is. The
largest are [US22](https://github.com/MESW-LES-2627/les-project-group-8/issues/77) and [US31](https://github.com/MESW-LES-2627/les-project-group-8/issues/84), at 3 points each.

**Throughput (retroactive):** 15 points, from the eight stories closed on
2026-11-20 ([US15](https://github.com/MESW-LES-2627/les-project-group-8/issues/75), [US17](https://github.com/MESW-LES-2627/les-project-group-8/issues/76), [US18](https://github.com/MESW-LES-2627/les-project-group-8/issues/78), [US19](https://github.com/MESW-LES-2627/les-project-group-8/issues/79), [US20](https://github.com/MESW-LES-2627/les-project-group-8/issues/80), [US22](https://github.com/MESW-LES-2627/les-project-group-8/issues/77), [US24](https://github.com/MESW-LES-2627/les-project-group-8/issues/82), [US31](https://github.com/MESW-LES-2627/les-project-group-8/issues/84)). [US23](https://github.com/MESW-LES-2627/les-project-group-8/issues/81) (1 point) is
still open; recount when the `iter-2` tag is cut. Because the points were set
after the work, this figure is a retroactive baseline, not a forecast that was
met. It is the baseline for planning iteration 3.

## Do differently

1. **Estimate every issue at iteration planning.** Stories, Tasks and Bugs get
   points in the board's `Estimate` field before work starts; story points and
   task points are reported separately.
2. **Move an issue to In progress when work starts.** Then the board's history
   gives a real cycle time for each issue, to check estimates against.

**Next action:** at iteration 3 planning, estimate every selected issue,
using the throughput above as the starting capacity.
