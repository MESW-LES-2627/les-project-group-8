# Retrospective

## What went well

The previous retrospective asked for issues framed so each of us could work
independently. Iteration 2 agreed the contracts up front in
[i02.d007.openapi.yaml](i02.d007.openapi.yaml), and US15, US17 and US22 started
in parallel on day one ([backlog](i02.d008-iteration-backlog.md)).

## What did not go well

We did not estimate the stories at iteration planning. We estimated them
afterwards, on 2026-11-20: closed stories sized from their merged PRs, open
stories by analogy to them. The points are in the
[backlog](i02.d008-iteration-backlog.md); how they were set is in the
[grilling record](../../assets/iterations/2/grilling-story-estimation.md).

The board's status history could not tell us how long each story took. US22
skipped "In progress", and every story was moved back to "To do" and forward
again on 2026-11-19, so only first transitions count, and those measure
calendar time, not effort.

No closed story is sized above 8. The largest are US22 and US31, at 3 points
each.

**Throughput (retroactive):** 15 points, from the eight stories closed so far
(US15, US17, US18, US19, US20, US22, US24, US31). US23 (1 point) is still open.
Because the points were set after the work, this figure is a retroactive
baseline, not a forecast that was met. It is the baseline for planning
iteration 3.

## Do differently

1. **Estimate every issue at iteration planning.** Stories, Tasks and Bugs get
   points on board 24's `Estimate` field before work starts; story points and
   task points are reported separately.
2. **Move an issue to In progress when work starts.** Then the board's history
   gives a real cycle time for each issue, to check estimates against.

**Next action:** at iteration 3 planning, estimate every selected issue,
using 15 points as the starting capacity.
