## Key human decision

**One component per story on the pool page.** Each story that shows
something on a Bet builds its own component and mounts it in
`BetCard.svelte` with one line
([iteration backlog](i02.d008-iteration-backlog.md)). The team chose it while
planning on 2026-11-08, because Iteration 1's "vertical" issues kept people
waiting on each other. With one component per story, stories can start in
parallel and merge conflicts stay small.

It stayed a human decision. In the planning session the assistant wrote the
answer down as "accept merge conflicts", and it was corrected
([c10781c](https://github.com/MESW-LES-2627/les-project-group-8/commit/c10781c)).
The assistant broke the rule twice more, both times by passing props through
`BetCard`: once while reviewing
[PR #85](https://github.com/MESW-LES-2627/les-project-group-8/pull/85) and once
while reviewing [PR #94](https://github.com/MESW-LES-2627/les-project-group-8/pull/94).
Both changes were dropped in favour of the team's rule.

Other decisions the team made itself: resolve per Bet, never per Pool, with
the Decider resolving; Records per Pool, with a Leaderboard that gives tied
Users the same rank; log every AI session cheaply and write this critique from
those logs.

## A concrete miss

Codex's US18 change ([PR #94](https://github.com/MESW-LES-2627/les-project-group-8/pull/94))
was meant to show the resolve form only to the Decider. It also hid the
"Resolved — winning outcome" line from everyone else, so participants could
no longer see who won. The review of #94 caught it, and
[72c6d43](https://github.com/MESW-LES-2627/les-project-group-8/commit/72c6d43)
in [PR #95](https://github.com/MESW-LES-2627/les-project-group-8/pull/95)
fixed it by dropping the `isDecider` condition around that line. No automated
test covers it, because the frontend has no test runner yet.

## Verdict

> **Draft, to be written by the team.** AI did most of the typing this
> iteration: code, tests, docs, issues and reviews. People decided what to
> build and how the work was split, and checked every change before it
> merged. The assistants' mistakes were caught by reviews and by
> people re-reading what the AI wrote down, so this was assistance, not
> replacement. What still has no automated check is the frontend.

## Personal accounts

Each person's own account of how they used AI this iteration.

### Alef Keuffer

Drafted by Claude Code from my raw entries and the grilling records, then
checked by me.

**A manual check nobody ran.** While planning US31
([record](../../assets/iterations/2/grilling-84-pool-leaderboard.md), Q3 and
Q6), the AI recommended checking 31.1–31.4 by hand and marking them "plus
manual UI check", like rows 16.1–16.2, 24.1 and 27.2. Those earlier checks had
never been done. I said so, and the
[testing doc](i02.d004-testing.md) now says "UI not yet checked: #33" for
them instead of claiming checks nobody ran. Every UI check moved to
Playwright: the harness
([PR #127](https://github.com/MESW-LES-2627/les-project-group-8/pull/127),
[ADR 0005](../../adr/0005-e2e-tests-use-a-throwaway-local-supabase.md)) and the
specs ([PR #128](https://github.com/MESW-LES-2627/les-project-group-8/pull/128),
[PR #130](https://github.com/MESW-LES-2627/les-project-group-8/pull/130),
[PR #132](https://github.com/MESW-LES-2627/les-project-group-8/pull/132)) now
run in CI.

Those tests then caught the AI twice, and found a real bug:

- The AI's first 16.1 check asserted that "Everyone's picks" was hidden before
  the deadline. `BetPicks.svelte` only renders it after the deadline, so the
  check could never fail. The spec review caught it, and it now checks that
  the Bet card doesn't name the other User
  ([ad9cb3c](https://github.com/MESW-LES-2627/les-project-group-8/commit/ad9cb3c)).
- The #124 run stored a deadline typed as 12:30 as 11:30 UTC: the server read
  it in its own time zone, not the User's. On Cloudflare, a User in Lisbon
  would get a summer deadline an hour late. I filed
  [#129](https://github.com/MESW-LES-2627/les-project-group-8/issues/129).
- The AI's first fix for #129 cleared the Name field when the deadline was
  filled, so the form never submitted. A field-value log in the e2e test
  found it. The fix
  ([PR #131](https://github.com/MESW-LES-2627/les-project-group-8/pull/131))
  converts the deadline in a `formdata` listener, and the test pins the
  browser to `Asia/Kolkata`.

**The Leaderboard before the deadline.** I asked for the Leaderboard to be
easier to reach
([record](../../assets/iterations/2/grilling-leaderboard-before-deadline.md)).
The AI recommended a side column on wide screens; I moved it above the Bets on
every screen instead. Its next question assumed the Leaderboard meant
something while the Pool is OPEN. When I questioned it, the AI found its
premise was wrong: it lists every User with a Pick at 0–0, all at rank 1. It
then recommended showing it as it was; I chose to hide it until the deadline.
When I asked what the API returned, it found the public endpoint listed the
same names and user ids, so I chose to hide it in the API too, not only in the
page as the AI recommended. That is US31's AC 31.6, shipped in
[PR #136](https://github.com/MESW-LES-2627/les-project-group-8/pull/136).

In both cases the AI's recommendations were reasonable defaults. The
decisions that mattered came from asking it to check what was actually true:
whether the checks had been run, and what the page and the API showed.

### João Luiz Cerqueira

While I(João) was doing the vision board, AI was very useless in understading the concept of vision and helping me write, even though I gave it relevant sources. The AI created the "Needs" in the table as concrete descriptions of stakeholder needs, such as "The organizer needs x, the user needs x", created complete made up business goals and overall required me to rewrite everything, and prompt it to rewrite what I did, then the result was good. My guess is that concepts like vision, mvp, are very subject to us, therefore AI requires a huge context and usually is better to write a full draft before commiting to AI use. I personally didn't use AI to review code to make myself more on pair with the code, but I apreciated AI review.
