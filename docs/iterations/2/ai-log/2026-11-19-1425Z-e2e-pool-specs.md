# E2E specs for creating a Pool, Picks, 16.1–16.2 and 27.2

- **Who:** Alef Keuffer.
- **Tools:** Claude Code (Claude Opus 5.5), `implement` and `code-review` skills
  from Matt Pocock's
  [Skills For Real Engineers](https://github.com/mattpocock/skills),
  Playwright 1.65.1.
- **Outcome:** `frontend/e2e/pools.spec.ts` for
  [#124](https://github.com/MESW-LES-2627/les-project-group-8/issues/124); the
  pick/detail, 16.1–16.2 and 27.2 rows in `i02.d004-testing.md` point at it.
- **Delegated:** writing the four specs (create a Pool; Picks on a radio and a
  dropdown Bet across reloads; a second User in a second browser context;
  the dropdown's ordered, labelled Outcomes). The review ran as two sub-agents
  (standards, spec).
- **Where it was wrong:** the first 16.1 check asserted that "Everyone's picks"
  was hidden, which `BetPicks.svelte` only renders after the deadline, so it
  could never fail; the spec reviewer caught it, and it now checks the Bet card
  doesn't name the other User. A first replacement checked the whole page and
  failed on the leaderboard, which lists every User with a Pick. The test title
  said "participant", not the glossary's "User".
- **How we checked:** `pnpm test:e2e --repeat-each=5` passes (50 runs);
  `pnpm check` and `pnpm test` pass.
- **Notes:** repeated runs exposed a race in the shared helpers: a form filled
  before SvelteKit hydrates is reset and posts nothing (the trace showed no
  POST). `signUp`, `logIn` and `createPool` now wait for `networkidle` first,
  through `waitForHydration` in `account.ts`.
